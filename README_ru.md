# Параметризация двумерных карт фотолюминесценции разложением по базисам

[English version](README.md)

В репозитории исследуется возможность представить двумерные карты
возбуждения–эмиссии фотолюминесценции (ФЛ) небольшим набором коэффициентов
разложения без потери точности решения обратной задачи. Целевая задача —
предсказание концентраций семи ионов по каждой карте ФЛ: Cu²⁺, Ni²⁺, Pb²⁺,
Al³⁺, Co²⁺, Cr³⁺ и NO₃⁻.

Основная идея состоит в замене карты размером `27 × 201` (5 427 значений
интенсивности) приблизительно 100 коэффициентами фиксированного функционального
базиса. Такое контролируемое снижение размерности позволяет применять компактные
классические регрессионные модели к спектроскопическому набору из 7 813 образцов
и сравнивать их со свёрточной нейронной сетью.

## Научный подход

Для карты $F(x,y)$ каждый трансформер вычисляет проекции или моменты вида

$$
c_k \approx \sum_{i,j} F(x_i,y_j)\,\phi_k(x_i,y_j)\,\Delta x\,\Delta y,
$$

где $\phi_k$ принадлежит одному из четырёх семейств базисных функций.
Увеличение максимального порядка увеличивает число сохраняемых коэффициентов.

- **Полиномиальные моменты** — центральные степенные моменты, упорядоченные по
  суммарной степени. Они дают интерпретируемое описание формы распределения, но
  не образуют ортогональный базис и могут становиться неустойчивыми на больших
  порядках. См. [MomentumTransformer2D](descriptions/MomentumTransformer2D.md).
- **Разложение Лежандра** — проекции на произведения полиномов Лежандра на
  нормированном прямоугольнике $[-1,1]^2$. Ортогональность обычно уменьшает
  избыточность признаков. См.
  [LegendreTransformer2D](descriptions/LegendreTransformer2D.md).
- **Разложение Фурье** — проекции на синусы и косинусы на нормированном
  прямоугольнике, включающие допустимые моды косинус–косинус,
  косинус–синус, синус–косинус и синус–синус. См.
  [FourierTransformer2D](descriptions/FourierTransformer2D.md).
- **Разложение Цернике** — радиальные и угловые моды Цернике на единичном круге.
  В текущем эксперименте физические границы равны `x=(375, 575)` нм и
  `y=(280, 410)` нм, фиксированный центр задан как `(441, 350)` в координатах
  `(x, y)`, а радиус достигает наиболее удалённого угла прямоугольника
  (`radius_mode="max"`). См.
  [ZernikeTransformer2D](descriptions/ZernikeTransformer2D.md).

Все реализации поддерживают интерфейс трансформеров scikit-learn и собраны в
[src.py](src.py). Краткое описание API приведено в
[руководстве по использованию](descriptions/Usage_Guide.md), а
[Momentum_transform.ipynb](Momentum_transform.ipynb) демонстрирует вычисление
коэффициентов и восстановление синтетических сигналов.

## Датасет и предобработка

Датасет не распространяется вместе с репозиторием. Его необходимо разместить в
корне проекта со следующей структурой:

```text
CD_HM_dataset/
├── Y_ions.csv
├── 1.csv
├── 2.csv
├── ...
└── 7813.csv
```

Файл `Y_ions.csv` должен использовать номер образца как индекс `num` и содержать
столбцы `Cu`, `Ni`, `Pb`, `Al`, `Co`, `Cr` и `NO3`. Каждый пронумерованный CSV
хранит одну карту ФЛ размером `27 × 201`. Строки соответствуют длинам волн
возбуждения от 280 до 410 нм, столбцы — длинам волн эмиссии от 375 до 575 нм.

При загрузке функция [import_df](src.py) заменяет отрицательные интенсивности на
пропущенные значения, а эксперимент затем заполняет их нулями. Все карты делятся
на единый глобальный максимум, вычисленный по полному датасету. Для каждого иона
и фолда CV `MinMaxScaler` обучается только на тренировочных целевых значениях;
перед вычислением метрик предсказания возвращаются к исходной шкале концентраций.

## Дизайн эксперимента

Основной эксперимент реализован в
[Experiment_1.ipynb](Experiment_1.ipynb):

- перемешанная 10-фолдовая кросс-валидация с `random_state=42`;
- отдельная регрессионная задача для каждого иона;
- порядки `0...13` для полиномиальных признаков, Лежандра и Цернике;
- порядки `0...7` для признаков Фурье;
- от 1 до 105 признаков для первых трёх сеток порядков и от 1 до 113 признаков
  Фурье;
- линейная регрессия (LR), случайный лес (RF), градиентный бустинг XGBoost (GB)
  и многослойный персептрон PyTorch (MLP);
- CNN-бейзлайн на PyTorch, обучаемый непосредственно на картах `27 × 201`;
- независимое сохранение MAE, RMSE и $R^2$ для каждого фолда.

Модели с ранней остановкой используют внутреннюю валидационную долю `2/7`.
Текущая CNN содержит два свёрточных слоя и скрытый линейный слой из 32 нейронов.
Базисные признаки кэшируются по типу базиса, порядку и фолду.

Основные результаты имеют структуру

```text
results[model][basis][ion][n_features][metric] = [10 значений по фолдам]
```

а CNN-бейзлайн сохраняется как

```text
baseline[ion][metric] = [10 значений по фолдам]
```

## Результаты

Архивные результаты исследования находятся в
[results/Experiment_1_3.json](results/Experiment_1_3.json) и
[results/Baseline_1_3.json](results/Baseline_1_3.json). Первый файл содержит
полные переборы для LR, RF и GB. Раздел MLP является частичным и содержит только
порядки 0–4 полиномиальных моментов, поэтому его нельзя трактовать как полное
сравнение четырёх базисов.

Архивный эксперимент позволяет осторожно сформулировать следующие выводы:

- около `80 ± 5` коэффициентов дают полезный компромисс между сохранением
  информации и сложностью модели, хотя оптимум зависит от иона;
- компактные классические модели способны достигать ошибок, сопоставимых с
  CNN-бейзлайном;
- признаки Лежандра и Фурье обычно относятся к наиболее устойчивым, поскольку
  соответствующие базисы ортогональны и покрывают всю прямоугольную карту;
- градиентный бустинг показывает наиболее стабильно высокое качество среди
  рассмотренных классических моделей;
- очень высокие порядки полиномиальных моментов могут увеличивать как среднюю
  ошибку, так и её дисперсию по фолдам.

Эти наблюдения относятся к данному датасету и протоколу и не являются заявлением
об универсальном превосходстве какого-либо базиса или модели.

### Примечание о версиях

Архивные JSON-файлы, использованные для анализа в отчёте, были получены до
добавления текущей конфигурации Цернике с фиксированным центром и максимальным
радиусом, а также до исправления CNN с двумя свёрточными слоями. Поэтому повторный
запуск текущего [Experiment_1.ipynb](Experiment_1.ipynb) может дать другие
результаты для Цернике и CNN. Существующие JSON следует рассматривать как
исторический снимок исследования, а новый запуск — как проверку текущей
реализации.

## Воспроизведение

### 1. Окружение

Рекомендуется Python 3.10 или новее.

```bash
git clone https://github.com/Gavr101/Spectroscopy_FL_7_momenta.git
cd Spectroscopy_FL_7_momenta
python -m venv .venv
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

В Windows PowerShell окружение активируется командой
`.venv\Scripts\Activate.ps1`, в Linux/macOS — `source .venv/bin/activate`.
Ноутбуки можно открывать непосредственно в VS Code. Для работы через JupyterLab
установите его отдельно:

```bash
python -m pip install jupyterlab
python -m jupyter lab
```

CUDA не обязательна: при отсутствии совместимого GPU PyTorch использует CPU.

### 2. Построение графиков без обучения

Откройте [Image_generation.ipynb](Image_generation.ipynb) для английских
графиков или
[Генерация изображений.ipynb](Генерация%20изображений.ipynb) для русских.
Оба ноутбука читают архивные JSON из `results/`, поэтому внешний датасет и
повторное обучение моделей не требуются.

Ноутбуки строят:

- зависимости MAE и $R^2$ от числа признаков для LR, RF и GB;
- четыре диаграммы по базисам со сравнением CNN, LR, RF и GB вблизи 80 признаков;
- три диаграммы по моделям со сравнением четырёх семейств базисов.

### 3. Полный повторный запуск

1. Разместите `CD_HM_dataset/` в корне репозитория.
2. Откройте [Experiment_1.ipynb](Experiment_1.ipynb) из корня проекта.
3. Чтобы сохранить архивные результаты, перед запуском задайте новые значения
   `RESULTS_PATH`, `BASELINE_PATH` и `CACHE_DIR`. Повторное использование старого
   кэша может смешать признаки, полученные разными конфигурациями трансформеров.
4. Выполните все ячейки. Ноутбук сохраняет результаты после каждого фолда и
   позволяет продолжить прерванный запуск.
5. Укажите новые JSON-файлы в ноутбуке визуализации.

Полный перебор требует значительных вычислительных ресурсов, особенно для MLP и
CNN.

  и восстановления сигналов.

## Ограничения воспроизводимости

- Исходный датасет необходимо получить отдельно.
- Глобальная нормировка интенсивности ФЛ использует информацию обо всех
  образцах, хотя целевой скейлер обучается внутри каждого тренировочного фолда.
- Перебор MLP в `Experiment_1_3.json` не завершён.
- Архивные результаты и текущая реализация Цернике/CNN соответствуют разным
  состояниям кода, как описано в примечании о версиях.
